### Why the read was empty (proved)

Spark 3.2 turned `spark.hadoopRDD.ignoreEmptySplits` on by default (SPARK-34809; off in Spark 2.4). `newAPIHadoopRDD` then drops every input split whose `getLength()` is 0. The HBase 1.4 `TableInputFormat` sizes each region's split from the region server's store-file size in whole megabytes, so a region with less than 1 MB on disk (or rows only in the memstore) gets length 0 and Spark never reads it: no error, no rows. ZooKeeper 3.6.3 and Hadoop 3.3.4 are not the cause.

Proof: a second trial commit on the scratch branch (e8af939: the Assess trial plus `spark.hadoopRDD.ignoreEmptySplits=false` on spark-job's tests through surefire and in `scripts/java17/spark-submit-jdk8.sh`, nothing else; never for merge), run [46010647637](https://github.com/ankursingh119/javapoc1.8/actions/runs/46010647637), against the Assess trial run 46007292373:
- JDK 8 job: `mvn -B install` and `mvn -B test` pass; the HBase end-to-end test runs and passes (before: `expected:<2> but was:<0>`).
- JDK 17 job: success; the production server's runs, through the stand-in that carries the setting, match `docs/reference/`.
- JDK 8 job's reference compare still fails, `report-20261113.csv has the header and no data rows`: that run starts the job through the test launcher `LocalJvmSparkJobLauncher`, which did not carry the setting. The one path without the setting stayed empty, so the discrimination holds both ways.

Consequence: on Spark 3.5 every way of starting the job must turn the setting off, or a batch reads only its larger regions and finishes COMPLETED with a short or empty report. In production, with regions of mixed size, that is a silently partial report.

### Design

Spark 3.5.5, Scala 2.12.18 (SA-3), the bundled HBase 1.4.13 client kept, ZooKeeper 3.6.3 and Hadoop 3.3.4 left as Spark 3.5 brings them (the trial shows the HBase 1.4 client works with them against HBase 1.4; ZooKeeper's `Received event is not valid: Closed` warning is harmless). Every commit that moves the versions also carries the read setting, so no commit has the empty read.

Where the setting lives is a person's decision, because the robust place is under `src/main`, which AC5 rules out (question on the card):

Every start path gets it: the pipeline, the HBase test, the VS Code debug run (`LocalJvmSparkJobLauncher`), the Docker cluster, and whatever cluster the cluster-move card chooses. AC5 needs that one exception, in words a person approves.
