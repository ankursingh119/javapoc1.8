### Pitfalls found (for Plan)

1. **Silent skip.** `SalesAggregatorHBaseTest` skips, it does not fail, when HBase is not reachable. A pipeline whose HBase start fails would still be green. The design needs a check that the two tests ran (for example, the surefire report for that class shows 0 skipped), or a wait-for-ports step that fails the job.
2. **`host.docker.internal` on Linux.** HBase advertises `host.docker.internal` (hbase-server-site.xml). On Windows Docker Desktop adds that name to the hosts file; on an Ubuntu runner it does not exist, so the client would find ZooKeeper and then fail to reach the region server. The runner needs `127.0.0.1 host.docker.internal` in `/etc/hosts`.
3. **Start-up time.** HBase in that image takes tens of seconds to serve; wait on the ports (and ideally the master) before `mvn test`.
4. **Tests run twice.** `mvn install` runs the tests too, so the card's "install, then test" runs each test twice and doubles the chance of the timing-sensitive red run. Plan decides whether `install -DskipTests` then `test` meets the agreed wording; the agreed wording is kept by default.
5. **JDK 17 job** will be red today (spark-job: `Unsupported class file major version 61`; workflow-app 22 of 30 error, estate brief). With `continue-on-error` it must not block; its result should still be readable.
6. **`dependency:go-offline`** must not be used (Spring 4.3's optional jasperreports dependency, estate brief).

### Design

One workflow file, `.github/workflows/ci.yml` (name "CI"), plus a few small scripts under `scripts/ci/`. Nothing under any `src/` changes.

- Triggers: `push` (all branches) and `pull_request` (AC1). `runs-on: ubuntu-latest` for both jobs.
- Job `jdk8` (display name "JDK 8", the future required check): checkout; `actions/setup-java` (Temurin 8, `cache: maven`); add `127.0.0.1 host.docker.internal` to the runner's `/etc/hosts` (pitfall 2); `docker compose -f docker/local/docker-compose.yml up -d hbase` (service `hbase` only, AC3); wait for HBase with `scripts/ci/wait-for-hbase.sh`; `mvn -B install`; `mvn -B test` (AC2, agreed wording kept, pitfall 4); then `scripts/ci/check-hbase-test-ran.sh`, which fails the job unless `spark-job/target/surefire-reports/TEST-com.example.salesbatch.spark.SalesAggregatorHBaseTest.xml` exists with tests > 0, skipped = 0, failures = 0, errors = 0 (AC3, the person's item 2). Job env: `SPARK_LOCAL_IP=127.0.0.1`.
- Always (`if: always()`): upload all `**/target/surefire-reports/` as an artifact, and on failure print `docker logs sales-hbase`, so a red run is readable.
- Job `jdk17` (display name "JDK 17 (allowed to fail)"): the same steps on Temurin 17, `continue-on-error: true` at job level so the run's conclusion stays green when it fails (AC4, pitfall 5). Its job result stays red and readable in the run.
- Wait for HBase: on Linux, docker-proxy accepts on published ports as soon as the container starts, so the test's own port probe (and a host-side port wait) says nothing about readiness. `wait-for-hbase.sh` polls inside the container (`echo status | docker exec -i sales-hbase hbase shell -n`, or the `/hbase/bin/hbase` path, Build settles the exact command) until it reports 1 active master and at least 1 live region server, at most 300 s, then fails the job with the container log (pitfall 3).
- No `dependency:go-offline` anywhere (pitfall 6). No retries of failed tests: a red run from the timing-sensitive workflow-app tests stays red and is noted in the card file (the card's agreed rule).
- Line endings: `.gitattributes` already forces LF on `*.sh`, so the mounted `start-hbase.sh` runs on Linux. New scripts are `*.sh` and get LF too; they are committed executable (`git update-index --chmod=+x`).
