### Findings that shape the design

1. **The local Spark launcher uses the server's own Java.** `LocalJvmSparkJobLauncher` (test source, unchangeable) starts the Scala job with `java.home` of the running server. With the server on JDK 17, the Spark 2.4.8 job would run on JDK 17 and fail (measured in the pipeline: spark-job's tests error on 17). So SBJ17-8's capture (`LocalDebugServer`, `spark.mode=local-jvm`) cannot show a real report on JDK 17 in this card. The brief's AC4 (a run on JDK 17 reaches COMPLETED with the reference report) needs another route: Plan item 2.
2. **common must keep Java 8 class files while built on JDK 17.** Prefer the compiler's `release 8` over `source`/`target 1.8`: it also refuses any JDK 9+ API at compile time. A check reads the class-file major version (52) (brief AC3).
3. **The JDK 17 job builds the whole reactor today**, so spark-job stops it. Proposed: `mvn -B -pl common,workflow-app -am install` and `test` in that job; spark-job stays only in the JDK 8 job.
4. **The workflow-app timing test fails now and then on JDK 8 as well** (seen in this trial, unchanged code). A red run of `SalesBatchProcessTest` is not by itself the change's fault; the card records each one (brief AC5, risks SBJ17-5 and SBJ17-7).
5. **Spring 4.3's optional jasperreports dependency** blocks `dependency:go-offline` (estate brief); it goes with Spring 5.3. No action, a note.
