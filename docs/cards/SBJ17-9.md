### Findings that shape the design

1. **The local Spark launcher uses the server's own Java.** `LocalJvmSparkJobLauncher` (test source, unchangeable) starts the Scala job with `java.home` of the running server. With the server on JDK 17, the Spark 2.4.8 job would run on JDK 17 and fail (measured in the pipeline: spark-job's tests error on 17). So SBJ17-8's capture (`LocalDebugServer`, `spark.mode=local-jvm`) cannot show a real report on JDK 17 in this card. The brief's AC4 (a run on JDK 17 reaches COMPLETED with the reference report) needs another route: Plan item 2.
2. **common must keep Java 8 class files while built on JDK 17.** Prefer the compiler's `release 8` over `source`/`target 1.8`: it also refuses any JDK 9+ API at compile time. A check reads the class-file major version (52) (brief AC3).
3. **The JDK 17 job builds the whole reactor today**, so spark-job stops it. Proposed: `mvn -B -pl common,workflow-app -am install` and `test` in that job; spark-job stays only in the JDK 8 job.
4. **The workflow-app timing test fails now and then on JDK 8 as well** (seen in this trial, unchanged code). A red run of `SalesBatchProcessTest` is not by itself the change's fault; the card records each one (brief AC5, risks SBJ17-5 and SBJ17-7).
5. **Spring 4.3's optional jasperreports dependency** blocks `dependency:go-offline` (estate brief); it goes with Spring 5.3. No action, a note.

### Design (on the proposed defaults)

- **Spring**: `spring.version` 5.3.39 (the last 5.3 release), nothing else, as in both trials. Jackson, H2, Jetty 9.4, Activiti 5.22, logback stay unless a test or the run forces a bump; each forced bump gets one line of reason here. No OpenRewrite recipe: the one change is a version property, and the `UpgradeToJava17` recipe would rewrite test files (SA-2) and is not needed for Java 8 class files.
- **Class files**: common and workflow-app keep Java 8 class files in this card (default of question item 3): on JDK 9 and later the compiler gets `release 8` through a profile activated by `<jdk>[9,)</jdk>` (it refuses JDK 9+ APIs), on JDK 8 `source`/`target` 1.8 as today. So the JDK 8 job stays unchanged and keeps proving Spring 5.3 there too, and the JDK 17 job builds and tests the same modules. Java 17 class files for workflow-app come with the card that retires the JDK 8 job.
- **JVM flags**: none unless a JDK 17 test or run needs one; then the smallest `--add-opens`, in surefire's `argLine` after JaCoCo's `@{argLine}` and in the README's run command.
- **Pipeline** (`ci.yml`, one line per step): job `jdk17` sets up JDK 8 and 17 (17 the default; the JDK 8 home for the Spark job), builds `-pl common,workflow-app -am` with `install` then `test`, builds spark-job's classes and classpath file with JDK 8, then runs the AC4 run and the AC3 and AC6 checks. It stays "allowed to fail" until merged; a person makes it required afterwards. Job `jdk8` gets the AC3 and AC6 checks only.
- **AC4 run** (`scripts/java17/`): `spark-submit-jdk8.sh`, a stand-in for `spark-submit` that runs `com.example.salesbatch.spark.SalesAggregator` on the JDK 8 home with `local[*]` and the spark-job classpath (the same command `LocalJvmSparkJobLauncher` builds), taking the business date from its last argument; `run-workflow-server.sh` starts the shaded `workflow-app.jar` (production `WorkflowServer`) on JDK 17 with `-Dspark.submit.command=` that script, `-Dspark.master=local[*]`, in-memory Activiti and a fresh report folder, then drives the three files through the REST flow and writes outcome files in SBJ17-8's format, so `scripts/reference/acceptance/AC4_compare_with_reference.sh`'s comparison logic applies unchanged (pointed at this output through `REFERENCE_RUN`).
- **Checks** (`scripts/java17/acceptance/`, names from the criteria): `AC3_common_targets_java8.sh` (every class under `common/target/classes` has major version 52), `AC6_javax_kept.sh` (grep rules above plus the `javax.servlet` imports of `LocalDebugServer` and the other test files, compared with `origin/main`), `AC5_tests_unchanged.sh` (no file under `*/src/test` changed since the merge base), `AC7_paths_allowed.sh` (diff against the merge base within the allowed folders). AC1 and AC2 are the jobs themselves.
- **README / .vscode**: the build sections say JDK 17 for common and workflow-app, JDK 8 for spark-job until its card; the local debug flow (`LocalDebugServer` with the child-JVM Spark job) stays on JDK 8 for now, because that launcher uses the server's own Java (Assess finding 1).
