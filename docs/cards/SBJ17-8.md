### Findings that shape the design

1. **Line endings follow the operating system.** `Files.write` uses the platform separator: the probe's reports on Windows end lines with CRLF; the pipeline (Linux) writes LF. A byte comparison would fail across machines for no business reason. The compare should normalise line endings (proposed default), and the ledger records it once.
2. **The rejection message contains the JDK's own text.** `(For input string: "notanumber")` is `NumberFormatException`'s message, not the application's. It is the same on JDK 17 today, but it is a platform source of difference, not the change's.
3. **Re-running the same business date "has not been verified"** (README section 5). Each reference run should start from an empty HBase (a fresh container in the pipeline) and use the three dates once.
4. **An empty report is the failure to catch.** A report of the header alone must fail the compare (brief AC4; the estate brief's Spark 3 trial wrote 0 rows with every unit test green).
5. The pipeline already starts HBase 1.4 in Docker on JDK 8 with the `host.docker.internal` hosts entry, so a capture-and-compare step fits in job `jdk8` after `mvn -B test` with no new service. The Spark cluster image (`salesbatch-runtime`) is not built in the pipeline today.

### Decisions for Plan, each with a proposed default

1. **Where the reference is captured.** (a) In the pipeline, job `jdk8`: HBase 1.4 in Docker, the Scala job in a child JVM with `local[*]`, on `main`'s commit; (b) on the person's machine (HBase and Spark in Docker in WSL, README 4.1). Default (a): repeatable, the same place every later card's compare runs, and this session cannot reach Docker. The regenerate document still gives the local commands (brief AC2).
2. **Spark mode for the reference.** (a) `local[*]` child JVM; (b) the Docker Spark cluster (needs the `salesbatch-runtime` image in the pipeline). Default (a): it runs the same Scala job against the same HBase; the cluster adds start-up cost and no report logic.
3. **How strict the compare is.** Reports: exact text, row order kept, line endings normalised, a header-only or missing report fails. Rejection: status FAILED, the full error text exactly, and no report file for its date. Default: as written. A later difference (for example the JDK's message text) is then shown to a person, not hidden.
4. **The compare in the pipeline.** (a) A step in job `jdk8` on every push, as a lasting guard; (b) a script a person runs by hand. Default (a); job `jdk17` gets it when that job can build.
