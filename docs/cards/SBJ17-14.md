### Decisions for Plan, each with my proposed default

1. **The production cluster.** An HBase 2 client is not supported against an HBase 1.4 server, so after this card the job and the workflow app need an HBase 2 cluster as well as Spark 3.5: EMR 5.36 can run neither. This is the open question on risk SBJ17-12. Default: this card moves the build, the pipeline and the local Docker stack; the documents describe the local stack as it now is and say the production cluster must move before any release, naming no EMR release until a person chooses one.
2. **Which documents.** Default: `ARCHITECTURE.md`, `latest-ARCHITECTURE.md`, `docs/project-summary.md`, the README and the three diagrams that name versions; history files (`docs/README.previous.md`, `docs/reference/`) stay as they are.
3. **Code untouched.** Default: nothing under `src/main` changes (the trial compiled unchanged), existing tests unchanged (SA-2); the deprecated HBase calls stay until an HBase 3 card.

Mine to choose (standing answer SA-3), to settle in Plan: HBase client 2.5.10 as in the trial (2.4 is end of life; a later 2.5 or 2.6 patch if Plan finds a reason); server image `harisekhon/hbase:2.1` passed but HBase 2.1 is itself end of life and the image is a third-party one, so Plan looks for a maintained HBase 2.5 image and keeps 2.1 only as a fallback.
